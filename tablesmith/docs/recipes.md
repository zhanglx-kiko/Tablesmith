# 处理步骤记录与重放

数据处理页面左下角的「处理步骤」区域按顺序记录在当前工作表上做过的操作，用于每个月对同类表格（同样的列）重复同一套处理。

## 记录哪些操作

| 操作 | 记录内容 |
|---|---|
| 清洗：去重（全部列或某一列）、删除空行、去除首尾空格 | 按哪一列去重 |
| 筛选 | 每个条件（列、比较方式、值）与「全部满足 / 任一满足」 |
| 计算列 | 新列名与计算方式 |
| 脱敏 | 列与脱敏方式 |
| 删列 | 删除的列名 |
| 透视 | 行、子行、列、值字段、汇总方式、显示方式、筛选、排序、总计 |
| 关联、纵向拼接 | 显示在列表里，但用到另一张表，含这一步时不能保存步骤文件 |

每一步显示执行前后的行数（如「8640→309 行」）。透视作用在当前已处理的表上，所以「先筛选再透视」重放时顺序一致。

## 操作

- **撤销**：撤销最后一步，表格回到上一步的结果。
- **重置**：清空全部步骤，回到原始表。「覆盖当前表」后步骤也清空（结果已写入表中）。
- **保存步骤**：保存为 `<工作表名>_处理步骤.tablesmith-steps.json`，位置与导出相同（上次导出目录，或弹出保存对话框）。
- **应用文件**：选一个步骤文件，在当前表上按顺序执行。
- **切换工作表时重放**：在 A 表上记录了步骤后切换到 B 表，面板提示「在当前表重放」，一键在 B 表上执行同样的步骤。

## 重放规则

- 步骤按列名（表头文字）引用列。执行前先检查每一步要用的列在当时是否存在（前面步骤新增的计算列算存在，删掉的列算不存在）；缺列时一步都不执行，提示「第 N 步（…）需要的列不存在：「列名」」，当前表不变。
- 重放不修改原始表，结果和手动逐步操作完全相同（`recipe.test.ts` 逐格比较）。
- 数值比较按原始值，所以同一份数据在 Excel 里存成 `199`、在 CSV 里写成 `199.00` 时，重放结果相同。

## 步骤文件格式

```json
{
  "version": 1,
  "name": "Sales Detail 处理步骤",
  "sourceHeaders": ["sale_id", "period_id", "..."],
  "steps": [
    { "op": "trim" },
    { "op": "filter", "match": "all", "conditions": [{ "column": "region", "operator": "equals", "value": "Northeast" }] },
    { "op": "dedupe", "columns": ["sale_id"] }
  ]
}
```

`op` 取值：`dedupe`、`removeEmptyRows`、`trim`、`filter`、`compute`、`deleteColumns`、`mask`、`pivot`。读入时逐项校验，未知操作、错误的比较方式或脱敏方式、类型不对的字段都会被拒绝，并指出是第几步。

实现：`src/services/recipeService.ts`、`src/components/StepsPanel.tsx`。

## 验证

- `src/services/recipe.test.ts`：在真实财务模型的 Sales Detail 上记录 6 步（去空格、两条件筛选、计算毛利、按 sale_id 去重、删两列、脱敏）加透视，与逐步手动调用结果逐格一致；在 `sales_detail.csv`（同样数据，30,710 个单元格文本不同）上重放，结果按值一致；保存再读入结果不变；缺列时不执行并指出第 3 步；7 种损坏的步骤文件被拒绝。用两种破坏重放的改动（漏掉最后一步、倒序执行）验证测试会失败。
- `tools/verify-steps-e2e.cjs`：真实 exe 中记录 4 步、撤销 1 步、保存文件并核对内容、切换到 CSV 重放；去重后的行数与直接从 CSV 原文统计的不同价格数（309）一致。
