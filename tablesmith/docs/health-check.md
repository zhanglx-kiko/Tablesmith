# 数据体检

数据源页面的「数据体检」按钮打开右侧面板，检查当前工作表。它只读：不修改任何原始值或显示值（`healthCheck.test.ts` 与 `tools/verify-health-e2e.cjs` 都验证这一点）。每条结果列出受影响的行，点「第 N 行」把表格滚动到该行并给单元格加上蓝色描边，描边保留到定位下一个单元格为止。如果该行被列筛选隐藏，会先清除筛选。

实现：`src/services/healthCheckService.ts`（规则）、`src/components/HealthPanel.tsx`（面板）。

## 规则

| 类型 | 级别 | 判断 |
|---|---|---|
| 唯一列重复 `duplicateKey` | 错误 | 表头像编号（订单号、编号、`*_id`、code、SKU…）且 90% 以上的值不同，或文本列 20 行以上且 98% 以上不同；列出重复值所在的行。外键（如单位表里的 `entity_id`）和金额列不算 |
| 公式错误 `formulaError` | 错误 | `#DIV/0!`、`#N/A`、`#REF!` 等错误值 |
| 整行重复 `duplicateRow` | 注意 | 所有列都相同（空行除外）；列出每组第一行之后的行 |
| 首尾空格 `whitespace` | 注意 | 值的首尾有空格 |
| 数字带格式字符 `numberAsText` | 注意 | 数字列（90% 以上是数字）里写成 `1,200`、`¥30`、`12 ` 的值；Excel 把它们当文本 |
| 非数字值 `nonNumeric` | 注意 | 数字列里的 `待定`、`N/A` 等 |
| 日期写法不一 `mixedDateFormat` | 注意 | 80% 以上是日期的列里出现多种写法（`2024-01-31` 与 `2024/1/31`），列出少数写法的行 |
| 分类写法不一 `variantSpelling` | 注意 | 分类列（不同值不多）里大小写、全角半角、空格不同的同一个值（`Online` / `online` / `ＯＮＬＩＮＥ`），列出少数写法的行 |
| 公式列里手填的值 `typedInFormulaColumn` | 注意 | 一列至少 60% 的有值行是同一个下拉填充的公式（`=B2*C2`、`=B3*C3`…按本行偏移比较），其余行直接填了数，源数据变了也不会跟着变；至少 4 行有值才检查。只对带公式的 xlsx / xls / xlsb 有效 |
| 空值 `missing` | 提示 | 一列至少一半的数据行有值时，列出其余空着的行 |
| 数量级异常 `outlier` | 提示 | 超过该列绝对值第 99 百分位的 10 倍（多输了 0、单位错）。至少 20 个数字才检查；编号列不检查；超过 1% 的值都超限时不报（该列没有稳定的量级） |

报表式工作表里的标题行（如「Unit volume (units)」后面全空）和表头式行（`Period ID | 2024-01 | …`）在数字列里不算数据：工作表至少有 3 个数字列，且某行在这些列里 80% 以上不是数字时，这行在空值、数字格式和数量级检查中被跳过。

数量级规则没有用四分位距（IQR）：真实金额分布偏斜，IQR 会把正常的大额借方标成异常（在财务模型的 `debit_usd` 上实测）。

## 验证

- `src/services/healthCheck.test.ts`：在真实财务模型和销售明细的每个工作表里，用 3 个固定随机种子在随机位置植入整行重复、首尾空格、带千分位的数字、非数字、公式错误、多两个 0 的金额，要求每个植入点都在对应的行和列被报出，未改动的列不新增结果；另有两项检查：当前最大值 2 倍的金额不报为异常，金额列不被当成唯一列。
- `sample-data/edge-cases/health_defects.csv`（`scripts/generate-health-fixture.py` 生成，植入位置在同名 `.planted.json`）：10 类缺陷各一处，单元测试和 e2e 都要求结果恰好是这 10 条。
- `tools/verify-health-e2e.cjs`：真实 exe 中打开面板、核对 10 条结果、点击第 223 行定位并检查描边、确认数据未变、深色模式截图。
