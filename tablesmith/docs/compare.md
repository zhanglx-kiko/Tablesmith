# 跨文件对比与合并

数据处理页面的「合并」标签页有三种方式，都以当前表为主表、另选一个已打开的文件（或其中一个工作表）：

| 方式 | 结果 |
|---|---|
| 横向关联（JOIN） | 按一列匹配，把另一张表的列补到当前表右侧，等同 VLOOKUP |
| 纵向拼接（Union） | 两张表上下相接，同名列对齐 |
| 对比差异 | 当前表作为旧版本、所选表作为新版本，列出新增、删除、修改的行 |

三种操作都会记录在「处理步骤」中，但用到另一张表，含这类步骤时不能保存步骤文件。

## 对比差异

- **匹配列**：只列出两张表都有的列，可多选（多列组合唯一时，如 `期间 + 产品`）。默认选中第一个像编号的列（`*_id`、编号、单号…）。
- **比较规则**：数字按值比较（`199` 与 `199.00` 相同，`1,200` 与 `1200` 算不同，因为前者是文本）；其余文字逐字比较，可勾选「忽略首尾空格」「忽略大小写」。
- **结果表**：每行一个变化，列为 `状态`（修改 / 新增 / 删除 / 重复键）、匹配列、`变化列`，然后每个比较列的「（旧）」「（新）」两列并排。未变的行不列出，数量显示在汇总里。结果表可以像普通表一样筛选、排序、导出。
- **不静默丢行**：
  - 匹配值在同一张表里重复出现的行不参与匹配，在结果中标为「重复键（旧表 / 新表）」，汇总里提示多选几列。
  - 匹配列为空的行不参与对比，汇总里给出行数。
  - 只在一张表里有的列不参与比较，汇总里列出列名。
- 两张表都不会被修改。

## 横向关联

- 匹配时去掉首尾空格，数字按值（`4000` 与 `4000.00` 匹配；`1,200` 与 `1200` 不匹配）。
- 另一张表里同一个键出现多次时，每行取第一条匹配（与 VLOOKUP 相同），并提示重复的键和次数。
- 完成后提示匹配和未匹配的行数；内连接时未匹配的行被去掉。
- 两张表都有的非匹配列保留两份，第二份改名为 `列名_(表名)`。

实现：`src/services/compareService.ts`（对比）、`joinSheets`（`src/services/dataProcessService.ts`）。

## 验证

- `src/services/compare.test.ts`：用真实 `sales_detail.csv` 作新表，工作簿的 Sales Detail（同样数据、3 万多个单元格文本不同）加上植入的改动作旧表：删 5 行、加 4 行、改 6 行的 1~2 列、复制 1 个键、清空 1 个键、打乱行序；3 个随机种子下，新增、删除、修改（含改了哪几列与差值）、重复键、空键都必须恰好等于植入内容，且其余 8,000 多行判为未变。用三种破坏性改动（重复键取第一条、按位置匹配、不按值比较数字）验证测试会失败。
- `src/services/join.test.ts`：销售明细按 `business_unit_id` 关联业务单元表，每行的单元名称与直接读 CSV 原文得到的一致；左连接 / 内连接的行数与未匹配数；重复键提示；数字键跨格式匹配。
- `tools/verify-compare-e2e.cjs`：真实 exe 中导入「上月」（由 CSV 生成，删 7 行、加 3 行、改 5 行）与本月文件，对比得到修改 5、新增 7、删除 3、未变 8,628，修改行恰好是改动的 5 个订单。
