# Prototype Spike

## 目标
用可丢弃原型回答一个明确问题，再把结论带回正式实现；原型不是生产代码。

## 分支选择
- 逻辑/状态机不确定：做终端或脚本原型，打印每一步状态变化。
- UI/交互不确定：做临时页面或路由，提供多个变体可切换。
- 数据模型不确定：用内存或 scratch 文件模拟，不依赖正式数据库。

## 原型规则
1. 明确问题：原型只回答一个主要问题。
2. 明显标记：文件名、目录名、注释写 `PROTOTYPE` 或 `SPIKE`。
3. 一条命令可运行：复用项目现有 task runner。
4. 默认不持久化：除非验证目标就是持久化。
5. 不追求工程化：不做复杂抽象、完整错误处理或长期测试。
6. 展示状态：每个操作后能看到关键状态变化。
7. 结束即处理：删除原型，或把结论吸收到正式代码/ADR/issue。

## 禁止事项
- 不把原型直接混进生产路径。
- 不在原型里写真实密钥、真实外部服务地址。
- 不让原型绕过正式权限或配置后长期存在。

## 输出格式
1. **原型要回答的问题**
2. **原型位置和运行命令**
3. **验证结果**
4. **采纳的设计结论**
5. **原型删除/吸收计划**
