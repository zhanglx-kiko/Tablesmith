# Code Audit & Documentation Drift

## 目标
发现真实、有证据、可修复的问题：逻辑缺陷、测试缺口、文档过期、注释误导、API 契约不一致。

## 审计原则
1. **证据优先**：每个问题引用具体文件、函数、文档段落、测试或复现路径。
2. **事实与推测分开**：不能把“可能更好”写成 bug。
3. **少而准**：优先高影响、高置信问题。
4. **文档视为契约**：README、API 文档、示例、配置说明与实现不一致必须指出。
5. **默认不改代码**：除非用户要求修复。

## 检查范围
- 逻辑：条件、空值、默认值、排序、分页、精度、编码、时区、异常、并发、事务。
- 安全：权限绕过、输入校验、敏感信息泄露、日志泄露。
- 架构：职责混杂、循环依赖、重复实现、配置散落、模型/类型/接口不同步。
- 测试：只测成功路径、断言过弱、fixture 脱节、flaky、文档承诺无测试。
- 文档：运行命令、API 字段、错误码、配置项、环境变量、故障手册。

## 严重性
- Critical：数据丢失、安全漏洞、权限绕过、生产大面积不可用。
- High：明确逻辑错误、关键链路失败、严重文档误导。
- Medium：边界缺失、错误处理不完整、测试不足导致较高回归风险。
- Low：局部文档过期、轻微一致性或可维护性问题。

## 输出格式
1. **审计范围**
2. **总体结论**
3. **问题清单**：严重性、证据、影响、修复建议、建议测试。
4. **文档漂移**
5. **测试缺口**
6. **建议优先级**
7. **未覆盖范围**
