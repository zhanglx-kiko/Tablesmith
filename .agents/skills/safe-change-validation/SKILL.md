# Safe Change Validation

## 目标
证明代码改动安全、可验证、可回归；不能用一句“测试通过”掩盖测试范围不足。

## 影响面分析
检查本轮是否涉及 API、CLI、UI、定时任务、消息队列、数据库、缓存、配置、权限、认证、审计、隐私、错误处理、并发、幂等、重试、超时、事务、文档、示例、迁移、生成代码、部署脚本。

## 风险分级
- 低风险：内部纯逻辑或小范围 UI，运行与改动直接相关的已有检查；只有存在真实行为缺口且新增测试能降低回归风险时才补单测，并按项目可用性运行 lint/typecheck 或手工验收。
- 中风险：跨模块或多调用方，选择与受影响链路匹配的单测 + 集成/页面/API 验证。
- 高风险：数据迁移、权限、支付、计费、文件、并发、外部接口，需集成/端到端/回滚验证。

## 测试矩阵
按受影响链路选择适用项：正常路径、空值/非法/边界输入、权限不足、下游失败/超时/部分成功、重复请求、并发、乱序事件、旧数据/旧配置、UI 空态/加载态/错误态。低风险改动不要求机械覆盖全部项目，未涉及项应标记为不适用。

## 验证顺序
1. 相关单元测试。
2. 相关集成/端到端测试。
3. lint/typecheck/format check。
4. 构建/打包。
5. 需要时执行迁移 dry-run、真实依赖 smoke、手工验收。

## 自检
- 无无关 diff。
- 无旧逻辑/旧字段/旧入口残留，除非明确写了兼容例外和删除计划。
- 无真实密钥、token、隐私数据日志。
- 文档与实现一致。
- 后台服务和临时资源已清理或明确保留原因。
- 若改动涉及发布、迁移或外部依赖，记录回滚/前滚验证和依赖状态；若启动过服务或浏览器，记录台账位置及最终清理状态。

## 输出格式
1. **影响链路**
2. **风险等级**
3. **测试矩阵**
4. **执行命令与结果**
5. **安全结论**
6. **残余风险**
7. **回滚/前滚与资源清理状态**
