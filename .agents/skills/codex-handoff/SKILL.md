# Codex Handoff

## 目标
把本轮上下文压缩成可继续执行的交接材料，让下一轮 Codex、ChatGPT 或人工不必重新摸索，同时避免泄露私有 chain-of-thought、密钥、隐私数据或无证据猜测。

## 必包含内容
- 用户目标和最终版本边界。
- 本轮已完成的改动。
- 关键设计决策和可公开依据。
- 修改文件清单。
- 已运行命令和结果。
- 未完成事项和下一步优先级。
- 风险、回滚、注意事项。
- 敏感信息说明：哪些配置本地存在但未公开。
- 后台资源清理状态：已清理/保留/无法确认。
- 当前分支、commit、工作区状态；无法获取时说明。
- 给下一轮 Codex 的可执行提示词。

## 禁止内容
- 不输出私有 chain-of-thought、隐藏推理过程、内部 scratchpad。
- 不写“我猜”“可能大概”作为事实；不确定内容必须标注未验证。
- 不包含真实密钥、cookie、token、私钥、完整连接串、生产隐私数据。
- 不把临时 debug 日志、失败草稿、无关探索堆进交接文档。
- 不承诺后台继续处理；只交接当前已经完成和已经验证的事实。

## 原则
1. 写事实，不写猜测。
2. 路径、命令、分支、commit、端口、PID 要准确。
3. 明确哪些问题已经排除，避免重复调查。
4. 对失败命令写清失败原因和下一步。
5. 对未运行的验证写清未运行原因和替代证据。
6. 对临时兼容、TODO、feature flag、DB migration 写清关闭条件。
7. 对资源清理引用 `dev-resource-cleanup` 的台账结论。
8. 对敏感配置引用 `security-secret-config-guard` 的脱敏口径。

## 建议收集命令
按项目实际情况选择，不要为了模板强行执行：
```bash
git status -sb
git diff --stat
git log -1 --oneline
```

如果本轮启动过后台资源，还应收集：
- 进程台账路径；
- 已清理的 PID/端口；
- 保留资源及原因；
- 无法确认归属的进程/端口。

## 交接粒度
- 长任务：按阶段列出已完成、未完成、风险、下一步。
- 审计任务：列出审计范围、证据、问题、修复建议、阻断项。
- 开发任务：列出修改文件、契约变化、测试命令、残留扫描。
- 部署任务：列出环境、配置占位符、脚本、回滚/前滚、验证命令。
- 部分完成：明确“已完成到哪里”，不要包装成封板完成。

## 交接读者检验
- 长任务、部分完成或跨会话继续的重要交接文档，交付前使用 `document-reader-validation`；简短单步交接按需执行。
- 让未参与讨论的接手者仅根据交接文档及其声明的引用材料，指出当前状态、已验证/未验证事项、失败路径、约束和第一步行动。
- 修订必须依赖作者补充背景才能继续的缺口，并记录检验状态；缺少隔离读者时标为“未独立验证”，继续交付可用交接材料。

## 输出格式
1. **目标**
2. **当前状态**
3. **已完成**
4. **修改文件**
5. **关键决策与依据**
6. **验证结果**
7. **未完成/下一步**
8. **风险与注意事项**
9. **敏感信息处理**
10. **资源清理状态**
11. **给下一轮 Codex 的建议提示词**
12. **读者检验**：执行时记录结论、关键发现、修订/复测结果及未覆盖范围。
