# Vertical Slice Planner

## 目标
把大版本拆成多轮 Codex 任务，但每轮都必须能独立验证一个真实业务路径；不把最终版本缩水，只是分轮实现。

## 原则
- 每个切片尽量贯穿 UI/API/数据/权限/测试/文档。
- 优先 AFK（away from keyboard，可由 Codex 自主完成）切片；确需人工决策才标 HITL（human in the loop，需要人工介入）。
- 先做主流程，再做异常、权限、批量、配置、审计、导入导出、运维。
- 每轮都要有验收命令和清理旧逻辑任务。

## 禁止拆法
- 不允许“第一轮只建表、第二轮只写后端、第三轮只写前端”。
- 不允许把测试和文档都推到最后。
- 不允许每轮都加兼容 shim，最后无人清理。

## 任务卡模板
- 标题
- 类型：AFK / HITL
- 目标
- 范围：包含 / 不包含
- 改动面：前端、后端、数据库、配置、测试、文档
- 验收标准
- 依赖
- 风险
- 禁止事项：兼容 shim、双入口、硬编码密钥、只改一侧

## 任务可执行性读者检验
- 正式分轮计划完成后、交付前使用 `document-reader-validation`，检验接手者仅凭计划及其声明的引用材料能否确定首轮起点、依赖顺序、每轮范围、验收和请求决策的条件。
- 重点检查跨轮依赖、禁止事项和收口责任是否需要作者临场解释；修订影响执行的缺口并复测，简短任务调整无需重跑整套检验。

## 输出格式
1. **V1.0 总目标**
2. **切片列表**：按依赖顺序编号。
3. **每个切片任务卡**
4. **推荐先做哪一轮**
5. **每轮完成后的验收/交接要求**
6. **读者检验**：执行时记录结论、阻断项及修订/复测结果；只对已检验的计划版本作结论。
